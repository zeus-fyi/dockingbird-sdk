# Troubleshooting index: agents, status, sync and clean

Find a message id below to see when Dockingbird prints that message. Add `--verbose` to a command and every message also shows its id. With `--json`, each envelope carries the id as its `id` key. Each id links to its entry in the [catalogue](../troubleshooting.md): the message text, the next step and the exit status. This page holds the 300 ids about starting agents, their status, sync, stop and clean.

## Docker, platform and setup

| Id | When it appears |
|---|---|
| [`STEP_TOOK_TOO_LONG`](../troubleshooting.md#step_took_too_long) | One of the steps Dockingbird asks Docker for while it sets itself up or starts, or starts an agent, took longer than Dockingbird waits, usually because the computer was busy. The message names the step; the next run picks up what Docker finished meanwhile. When the step was sending an agent its task, the agent is running and the task may have reached it: `dockingbird status NAME` shows what it works on. |

## Update

| Id | When it appears |
|---|---|
| [`SESSION_RESUMED_AFTER_UPDATE`](../troubleshooting.md#session_resumed_after_update) | Dockingbird moved an agent to a new version, or to new code of the same version, at a stopping point and resumed its conversation; the agent's tool reads this line as it starts again. When the move to a new engine failed and the agent came back to the version it ran, the line says so. When the move ended a command the agent ran in the background, the line also asks the agent to check that command's effect before it runs it again. |
| [`AGENTS_RUNNING_UPDATE_REFUSED`](../troubleshooting.md#agents_running_update_refused) | You ran `dockingbird update` while agents are working, and Dockingbird couldn't keep a copy of the version they run, so it changed nothing and waits for you: the copy's install failed, or an older copy is still in use. The same lines show when agents started while an update was finishing. |
| [`CLEAN_ALL_NO_SYNC_LIST`](../troubleshooting.md#clean_all_no_sync_list) | You ran `dockingbird clean --all` while an update is half done, so Dockingbird can't list the commits you haven't synced. |

## Agents: starting

|---|---|

| [`AGENT_LEAVE_HINT`](../troubleshooting.md#agent_leave_hint) | The last start line when the agent takes this terminal (a Codex start that waits for Enter prints one more): closing the window leaves it working. |
| [`CODEX_PRESS_ENTER`](../troubleshooting.md#codex_press_enter) | A Codex start at a terminal where Codex will ask for folder access: Dockingbird printed its note about that question and waits for Enter before Codex opens its screen, which hides every line above. Press Enter (any line goes on; ctrl-C ends the start before Codex runs, and a new agent ended so is not kept: `status` lists none of it), then press Enter again at Codex's folder question before you type. |
| [`NAME_OTHER_TOOL`](../troubleshooting.md#name_other_tool) | You picked a name with `--as` that belongs to the other tool: a Claude name for Codex, or the reverse. A name stays with the tool that first used it while its agent runs or its work is kept; for an agent that works without a terminal, the message gives the send that reaches it; for kept work, it says where it is and gives the command that picks it up from where you are; for an agent of the other tool that ended, it gives the command that continues it; for a name whose last agent ran as neither a Claude nor a Codex (one `dockingbird native launch` opened with another harness), nothing continues it, and the message says to pick another name. For kept work, an agent that ended, or a name neither tool continues, the message also gives the command that deletes the agent's copy, results and history, `dockingbird clean NAME --yes`, which frees the name. |
| [`NAME_OTHER_COMMAND`](../troubleshooting.md#name_other_command) | You picked up an agent with `--as` by a command other than the one it ran: a config's command for an agent of `dockingbird claude` or `codex`, the tool's own command for an agent of a config's command, or a terminal for an agent that worked without one, whose messages that terminal can't read. An agent goes on only as it ran, so the message gives the command that continues it; nothing was started. With `dockingbird claude` or `codex`, it says so only for an agent whose config runs it without a terminal. When the agent's config is no longer the one that gives its command here (a renamed config file, or the command moved to another config), nothing can continue it, and the message gives the bare start of a new agent instead. |
| [`COPY_OTHER_ENVIRONMENT`](../troubleshooting.md#copy_other_environment) | You started an agent by name, and the work kept under that name ran in another setup, such as another command's or one without a terminal. This start can't take it, so nothing was started; `dockingbird status NAME` gives the command that picks it up. |
| [`NAME_HAS_WORK_ELSEWHERE`](../troubleshooting.md#name_has_work_elsewhere) | You started an agent by name, and its work is kept on another branch or in another checkout. The message gives the command that picks it up from where you are; nothing was copied or started. |
| [`NAME_ENDED_ELSEWHERE`](../troubleshooting.md#name_ended_elsewhere) | You continued an agent with `dockingbird claude --as NAME` (or `codex`), and it last worked on another repository. Its conversation is about that code, so the message gives the command that continues it there, from where you are; nothing was started. |
| [`NAME_HAS_WORK_KEPT`](../troubleshooting.md#name_has_work_kept) | You started an agent with `--as` and `--new`, but that name's work is still kept. A name has one copy, so the message gives the command that picks the work up from where you are, or starts a new agent under a name of its own; nothing was copied or started. Every form also gives the command that deletes the agent's copy, results and history, `dockingbird clean NAME --yes`, which frees the name. |
| [`NAME_INVALID`](../troubleshooting.md#name_invalid) | You gave `--as` a name with characters an agent name can't have, or `host`, Dockingbird's name for you, the parent; or you gave `dockingbird mcp install --connected` a name with such characters. Names use lowercase letters, digits and `-`; for a name with other characters, the `--as` message suggests the closest one. |
| [`START_CONFIG_FIXED`](../troubleshooting.md#start_config_fixed) | You started a config's command with `--harness`, `--terminal`, `--bus` or `--egress`, and the config file fixes that setting to another value (a start on the bus passes `--bus`, so a command whose `mode` is `terminal` is refused there instead of taking the terminal the start runs on). Nothing was started; drop the flag, or change the file. |
| [`START_CPUS_INVALID`](../troubleshooting.md#start_cpus_invalid) | You gave `--cpus` a value that isn't a number of CPUs above zero: a whole number such as `2`, or one with a point such as `1.5` (at most nine digits after it). Nothing was started. |
| [`START_MEMORY_INVALID`](../troubleshooting.md#start_memory_invalid) | You gave `--memory` a value that isn't a size: a whole number above zero followed by its unit, `b`, `k`, `m` or `g` (`512m`, `4g`). Nothing was started. |
| [`START_CPU_SHARES_INVALID`](../troubleshooting.md#start_cpu_shares_invalid) | You gave `start --cpu-shares` (or a config's command) a value that isn't a whole CPU weight from 2 to 262144, such as `1024`. Nothing was started. |
| [`START_PIDS_LIMIT_INVALID`](../troubleshooting.md#start_pids_limit_invalid) | You gave `start --pids-limit` a value that isn't a whole count of processes from 1 to 4194304, such as `512`. Nothing was started. |
| [`START_COMPACT_AT_INVALID`](../troubleshooting.md#start_compact_at_invalid) | You gave `start --compact-at` (or a config's command) a value in no form Claude Code's own `/autocompact` takes (`auto`, a token count, `500k`, `1M`, or `500` for 500 thousand), or outside the agent's range: for a Claude Code agent 100K to 1M, the range its docs give (another value it would clamp or ignore without a word); for a Codex agent any count of tokens, since Codex documents no range. Nothing was started. |
| [`START_SESSION_HOURS_INVALID`](../troubleshooting.md#start_session_hours_invalid) | You gave `start --session-hours` (or a config's command) a value that isn't a whole number of hours from 1 to 168, such as `48`: the most the agent may run before it ends itself. Nothing was started. |
| [`START_SWARM_INVALID`](../troubleshooting.md#start_swarm_invalid) | You gave `start --swarm` (or a config's command) a name that isn't a swarm's name: lowercase letters, digits and `-`, up to 63 characters, the same rule as an agent's name in `--as`. Nothing was started. |
| [`START_ROLE_INVALID`](../troubleshooting.md#start_role_invalid) | You gave `start --role` a name that isn't a role's name: lowercase letters, digits and `-`, up to 63 characters. Nothing was started. |
| [`START_ROLE_NEEDS_SWARM`](../troubleshooting.md#start_role_needs_swarm) | You gave `start --role` (or the engine's own `--engine`) without `--swarm`. A role is a place in a swarm, so name the swarm the agent joins. Nothing was started. |
| [`START_ENGINE_INVALID`](../troubleshooting.md#start_engine_invalid) | You gave `start --engine`, the fleet engine's own mark, a value that isn't a workload's id (a UUID). A person never types it; drop it. Nothing was started. |
| [`START_CONFIG_NEEDS_ENGINE`](../troubleshooting.md#start_config_needs_engine) | You gave `start --config` without `--engine`. The file is the fleet engine's own, written for one start of a swarm's role; a start of yours reads your checkout's configs instead. A person never types either; drop it. Nothing was started. |
| [`START_SEND_TO_NEEDS_ROLE`](../troubleshooting.md#start_send_to_needs_role) | You gave `start --send-to` without `--role`. It names the roles an agent of that role may message besides its parent, which the fleet engine gives with the role. A person never types it; drop it. Nothing was started. |
| [`START_SEND_TO_INVALID`](../troubleshooting.md#start_send_to_invalid) | You gave `start --send-to` a word that is neither `-` nor role names joined by commas. The fleet engine gives it with the role; a person never types it, so drop it. Nothing was started. |
| [`START_EGRESS_UNTRUSTED`](../troubleshooting.md#start_egress_untrusted) | You started a command from a repo's own `.dockingbird/` folder, in a checkout that isn't trusted on this Mac (one you marked with `dockingbird trust --off`, or one with no mark while `config.toml` in Dockingbird's folder says `trust = "untrusted"`), whose `egress` would let the agent reach more than this computer's default does: `full`, or an `allow` entry the default's hosts don't cover. A repo you don't trust can't widen what its agents reach, so nothing was started. Keep to hosts the default covers, use `models`, or mark the checkout trusted with `dockingbird trust`. |
| [`EGRESS_PROXY_FAILED`](../troubleshooting.md#egress_proxy_failed) | You started an agent whose egress is `models` or `allowlist`, and the proxy that keeps it to its allowed hosts didn't start or didn't answer in time. Everything the start made was removed. The message shows the proxy's last lines, or what Docker said when it printed none. |
| [`EGRESS_LOG_ROW`](../troubleshooting.md#egress_log_row) | One line of an agent's egress proxy's log, under the message that says the proxy didn't start. |
| [`START_NETWORK_POOLS_FULL`](../troubleshooting.md#start_network_pools_full) | You started an agent, and Docker couldn't make the agent's own network: every address range of its address pools is taken. Docker's default pools hold about 30 networks, shared by every Docker network on this computer: your running agents', another Dockingbird folder's and other programs'. Dockingbird removed its own unused networks first, so nothing was started. `docker network ls` lists the networks; `docker network prune` removes every network no container uses, other programs' included; or add pools to Docker's `default-address-pools` setting (in Docker Desktop: Settings > Docker Engine), then run the command again. |
| [`EGRESS_FILE_INVALID`](../troubleshooting.md#egress_file_invalid) | You started an agent, ran `dockingbird status` or ran `dockingbird egress`, and `egress.toml` in Dockingbird's folder, the file `dockingbird egress` writes, can't be read as written: it isn't TOML, it has a line other than `egress` and `allow`, `egress` is missing or isn't one of the four modes, `allow` is missing under `allowlist`, is left over beside another mode or has something that isn't a host or a preset, or the file is a link or too large, or is a folder. No agent starts on a guess, so fix the file, or remove it with `dockingbird egress --reset` to go back to Dockingbird's own default. A folder is the one thing `dockingbird egress --reset` and a new mode both refuse and leave as it is, since it may be yours: move it aside (rename it, or move it out of Dockingbird's folder), then run the command again. Only `dockingbird clean --all`, which empties Dockingbird's folder, removes it with the rest. `dockingbird status` only looks, so it says this in the place of its egress line and still exits 0; a start and `dockingbird egress` exit 1. |
| [`EGRESS_SHOWN`](../troubleshooting.md#egress_shown) | You ran `dockingbird egress` with no argument: what new agents may reach, the `allow` list of `allowlist`, and whether `egress.toml` sets it or it is Dockingbird's own default. |
| [`EGRESS_SET`](../troubleshooting.md#egress_set) | You ran `dockingbird egress` with a mode, such as `models` or `allowlist --allow github`, and it wrote `egress.toml`. New agents get that; agents already running keep what they started with. |
| [`EGRESS_RESET`](../troubleshooting.md#egress_reset) | You ran `dockingbird egress --reset`, which removes `egress.toml` (or finds none). New agents get Dockingbird's own default again. |
| [`EGRESS_ENTRY_INVALID`](../troubleshooting.md#egress_entry_invalid) | You gave `dockingbird egress` an `--allow` entry that isn't a host such as `docs.python.org`, or `*.corp.example` for every name under it, or a preset (`registries`, `github`), or more entries than an allow list takes. The message names the entry by its number among your `--allow` options, and nothing was written. |
| [`AGENT_RUNNING_ARGS`](../troubleshooting.md#agent_running_args) | You gave `--as` with arguments for the tool, with `--egress`, or with `--new`, for an agent that is already running. A running agent can't take new arguments or another egress, and `--new` can't take its name; you can reconnect to it or stop it, and with `--new` start a new agent under a name of its own. With `dockingbird start --as`, the agent runs already, so the message says how to send it a task instead. `dockingbird claude --as NAME` (or `codex`) of an agent that works on the bus, or whose container is gone, says the same: there is no terminal to reconnect to. Dockingbird itself refuses to start a second agent under a name that is running, so the same words come back when an agent started between the check and the start. The still-starting form: another command is starting the agent right now; a task you send reaches it once it runs. When that command starts it at a terminal (Codex waiting there for Enter before it opens, say), the message says to use it in that terminal instead: a terminal agent reads a task when you type in it. The form that asks you to run the command again: another command is starting an agent with no name yet, which may be this one, and is still making its copy, which takes minutes for a big repository's first agent. |
| [`AGENT_UNKNOWN`](../troubleshooting.md#agent_unknown) | You named an agent, with `stop`, `status`, `send`, `read`, `results` or `inspect config --agent`, that isn't running and has no work kept, or one that isn't running with `wait`. |
| [`START_MERGE_OFFER`](../troubleshooting.md#start_merge_offer) | You started an agent on a branch where you and the agents both have new commits. Dockingbird offers to merge theirs into yours first, so the agent starts from both. |
| [`BOTH_MOVED_ROW`](../troubleshooting.md#both_moved_row) | One commit in a list of new commits on both sides, yours or the agents'. |
