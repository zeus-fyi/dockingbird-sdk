# Troubleshooting index: benchmark jobs

Find a message id below to see when Dockingbird prints that message. Add `--verbose` to a command and every message also shows its id. With `--json`, each envelope carries the id as its `id` key. Each id links to its entry in the [catalogue](../troubleshooting.md): the message text, the next step and the exit status. This page holds the 51 ids about Harbor benchmark jobs.

| Id | When it appears |
|---|---|
| [`HARBOR_PIN_INVALID`](../troubleshooting.md#harbor_pin_invalid) | You ran `dockingbird harbor` with a `--harbor-commit` that isn't a full commit, or in a task repository whose `.github/workflows/validate-harbor.yml` names a Harbor commit that isn't one, or can't be read safely. |
| [`HARBOR_PIN`](../troubleshooting.md#harbor_pin) | You ran `dockingbird harbor run`, `baseline`, `check` or `version`: the Harbor commit it uses, and whether it came from `--harbor-commit`, from the task repository's CI workflow or from Dockingbird's own pin. |
| [`HARBOR_PIN_NOT_FOUND`](../troubleshooting.md#harbor_pin_not_found) | Dockingbird cloned Harbor to install a commit, and Harbor's repository has no such commit. |
| [`HARBOR_INSTALLING`](../troubleshooting.md#harbor_installing) | A `dockingbird harbor` command needed a Harbor commit that isn't installed yet, and installs it, once per commit: the clone, the packages of Harbor's own lock file, then the checks. |
| [`HARBOR_OUTPUT_LINE`](../troubleshooting.md#harbor_output_line) | One of the last lines a failed step of Harbor's install printed, or one mise printed while it read or installed a repo's tool versions (under a failure's message, and each as it comes when you start with `--verbose`), shown with any control character escaped. |
| [`HARBOR_INSTALL_FAILED`](../troubleshooting.md#harbor_install_failed) | A step of Harbor's install failed, ran past the install's time bound, or couldn't run (uv missing from your PATH, for one), or the commit's lock couldn't be used: it has a package with no wheel for this computer (the install builds none), or it can't be read. |
| [`HARBOR_COMMIT_UNTESTED`](../troubleshooting.md#harbor_commit_untested) | Harbor was installed at a commit whose private APIs differ from those Dockingbird's Harbor plugin was tested on. |
| [`HARBOR_VERSION`](../troubleshooting.md#harbor_version) | You ran `dockingbird harbor version`: whether the Harbor commit in use is installed, and the folder it is (or will be) installed in. |
| [`HARBOR_NOT_A_TASK`](../troubleshooting.md#harbor_not_a_task) | You ran `dockingbird harbor run` or `baseline` in a folder, or named one with `-p`, that has no `task.toml`, so it isn't a Harbor task. |
| [`HARBOR_TASK_INVALID`](../troubleshooting.md#harbor_task_invalid) | The task's `task.toml` couldn't be used: it is too large, a link, not UTF-8 or not TOML, or a setting Dockingbird reads (the task's name, which Harbor takes only as org/name, its operating system, its timeouts, resources or network modes) isn't of the kind Harbor takes, or its count of cpus or of memory is below zero or more than Docker can take, so no job with it would run anywhere. |
| [`HARBOR_TASK_UNSUPPORTED`](../troubleshooting.md#harbor_task_unsupported) | The task's `task.toml` has steps, or sets its operating system to Windows. |
| [`HARBOR_NETWORK_POLICY_REFUSED`](../troubleshooting.md#harbor_network_policy_refused) | The task's `task.toml` asks, in its `[environment]`, `[agent]`, `[verifier]` or `[verifier.environment]` section, for a network other than public, or turns the internet off. |
| [`HARBOR_TASK_LAYOUT`](../troubleshooting.md#harbor_task_layout) | You ran `dockingbird harbor run` or `baseline` on a task folder that Harbor wouldn't run as one task: its `environment` folder, its `instruction.md` or its `tests/test.sh` is missing or is a link, it has an `environment/.env`, which compose would read on this Mac, its `environment/Dockerfile` is a link leading outside that folder, or a `Dockerfile.rego` lies beside it, which Docker's build would read on this Mac as a build policy, or a folder inside it has another `task.toml`, which Harbor would run instead. |
| [`HARBOR_COMPOSE_REFUSED`](../troubleshooting.md#harbor_compose_refused) | A compose file of the job (the task's `environment/docker-compose.yaml`, the `tests/docker-compose.yaml` of a verifier that runs in a container of its own, or one you gave with `--extra-docker-compose`) sets something Dockingbird doesn't run: a key outside the ones that keep the task's containers to themselves (`ports`, `volumes` or `privileged`, for example), a build folder outside the file's own folder, a build's Dockerfile that is a link leading outside the file's own folder, or a `.rego` file beside it, the host's or another container's network, a network Dockingbird didn't make, a label of Dockingbird's or compose's, or a build path or label that compose would interpolate (`$`). |
| [`HARBOR_COMPOSE_INVALID`](../troubleshooting.md#harbor_compose_invalid) | A compose file of the job (the task's, the verifier's own or one you gave) couldn't be checked: it is too large, missing, a link, not UTF-8 or not one YAML document, it uses a YAML alias or a YAML tag, it nests deeper than a compose file does, or has something other than what a compose file has where Dockingbird reads it. |
| [`HARBOR_AGENT_UNSUPPORTED`](../troubleshooting.md#harbor_agent_unsupported) | You gave `dockingbird harbor run` an agent with `-a` that Dockingbird doesn't run: it runs Harbor's oracle, nop and claude-code agents, since any other needs a key in its environment, which Dockingbird never hands Harbor that way. |
| [`HARBOR_ENVIRONMENT_UNSUPPORTED`](../troubleshooting.md#harbor_environment_unsupported) | You gave `dockingbird harbor run` an environment with `-e` other than docker. |
| [`HARBOR_OPTION_REFUSED`](../troubleshooting.md#harbor_option_refused) | You gave `dockingbird harbor run` an option Dockingbird doesn't pass on to Harbor, and nothing ran. |
| [`HARBOR_JOB_NAME_INVALID`](../troubleshooting.md#harbor_job_name_invalid) | You gave `dockingbird harbor run` a `--job-name` that isn't a job name: lowercase letters, digits and hyphens, starting with a letter or digit, up to the length the message names. |
| [`HARBOR_RUNNING`](../troubleshooting.md#harbor_running) | You ran `dockingbird harbor run` or `baseline`: the job's folder is made and Harbor is about to start. |
| [`HARBOR_JOB_DONE`](../troubleshooting.md#harbor_job_done) | A job of `dockingbird harbor run` or `baseline` ended: one row for each trial that finished (its name, its agent, its reward, how long it ran and, if it failed, the kind of error), then the job's folder. |
| [`HARBOR_TRIAL_ROW`](../troubleshooting.md#harbor_trial_row) | One trial of a Harbor job, in the lists `harbor run`, `baseline` and `harbor results` print: its name, its agent, the reward it earned (`-` when it has none), how long it ran and, when it failed, the kind of error. |
| [`HARBOR_LEFTOVERS_REMOVED`](../troubleshooting.md#harbor_leftovers_removed) | A Harbor job ended and Dockingbird cleaned up after it: the Docker images the job built are removed, each by its exact id; an image a running container still uses stays; and the containers, networks and volumes the job left behind, if any, are removed too. |
| [`HARBOR_IMAGES_NOT_MADE`](../troubleshooting.md#harbor_images_not_made) | A Harbor job ended, and Docker held images that weren't there when it started but that the job didn't make: another program's or another Dockingbird folder's, a base image the job's task pulled, or another job's. |
| [`HARBOR_IMAGE_KEPT`](../troubleshooting.md#harbor_image_kept) | Docker refused to remove an image a Harbor job built, for a reason other than a container using it. |
| [`HARBOR_BASELINE_OK`](../troubleshooting.md#harbor_baseline_ok) | You ran `dockingbird harbor baseline`: the task's oracle run scored 1 on every attempt and its nop run scored 0, so the task's checks pass. |
| [`HARBOR_BASELINE_FAILED`](../troubleshooting.md#harbor_baseline_failed) | You ran `dockingbird harbor baseline` and it found a problem with the task: a trial that scored other than 1 for the oracle or 0 for nop, shown with the last lines its verifier printed; a trial that hit an error, with the last lines of its output; a trial with no result; a job that didn't run the task Dockingbird checked; or a job that ended with a failing status before a verdict. |
| [`HARBOR_JOB_UNEXPECTED`](../troubleshooting.md#harbor_job_unexpected) | A Harbor job ended and what it left doesn't match what Dockingbird started: Harbor wrote no result for the job, the job ran another task than the one Dockingbird checked, or it ran another number of trials than were planned. |
| [`HARBOR_RESOURCES_OVER_VM`](../troubleshooting.md#harbor_resources_over_vm) | The task asks for more cpus or more memory than Docker's virtual machine has. |
| [`HARBOR_COMPOSE_MISSING`](../troubleshooting.md#harbor_compose_missing) | You ran a `dockingbird harbor` command that runs a job, and Docker has no compose plugin, which Harbor needs. |
| [`HARBOR_DOCKER_FAILED`](../troubleshooting.md#harbor_docker_failed) | A docker command a `dockingbird harbor` command runs failed; the message gives the command and Docker's own words. |
| [`HARBOR_JOB_RUNNING`](../troubleshooting.md#harbor_job_running) | You ran `dockingbird harbor run` or `baseline` with a job name that another `dockingbird harbor` command is still running. |
| [`HARBOR_PROGRAM_MISSING`](../troubleshooting.md#harbor_program_missing) | You ran `dockingbird harbor run` or `baseline`, and the Harbor that Dockingbird installed can no longer be started: its folder was changed or broken after the install. |
| [`HARBOR_JOBS_DIR_MISSING`](../troubleshooting.md#harbor_jobs_dir_missing) | You gave `dockingbird harbor run` or `baseline` a `-o` folder that isn't there, or isn't a folder. |
| [`HARBOR_RECORD_FAILED`](../troubleshooting.md#harbor_record_failed) | Dockingbird's own record of a Harbor job (`dockingbird.json` in the job's folder) couldn't be written, or under `--json` its log (`dockingbird.log`) couldn't be opened, or the job's folder itself couldn't be made; the message names the folder and what the system said, and the command exits 1. |
| [`HARBOR_SIGNIN_TOO_SHORT`](../troubleshooting.md#harbor_signin_too_short) | You ran `dockingbird harbor run -a claude-code` with no saved Claude key or token, and the Claude sign-in on this Mac isn't known to last the whole trial. |
| [`HARBOR_NO_SIGNIN`](../troubleshooting.md#harbor_no_signin) | You ran `dockingbird harbor run -a claude-code`, and Dockingbird has neither a saved Claude key or token nor a Claude sign-in to give the trial. |
| [`HARBOR_COMMIT_UNTESTED_AGENT`](../troubleshooting.md#harbor_commit_untested_agent) | You ran `dockingbird harbor run -a claude-code` on a Harbor commit that Dockingbird's plugin wasn't tested with, taken from the task repository's pin or Dockingbird's default: the claude-code agent relies on parts of Harbor that may differ there, so it doesn't run. |
| [`HARBOR_LEND_FAILED`](../troubleshooting.md#harbor_lend_failed) | You ran `dockingbird harbor run -a claude-code`, and Dockingbird couldn't get the Claude sign-in or key for the trial: its store refused, Docker failed, or the answer couldn't be read. |
| [`HARBOR_JOBS`](../troubleshooting.md#harbor_jobs) | You ran `dockingbird harbor jobs`: the Harbor jobs on this Mac, newest first, one row each. |
| [`HARBOR_JOBS_ROW`](../troubleshooting.md#harbor_jobs_row) | One job of the list `dockingbird harbor jobs` prints: its name, its task, its agent, whether it is running, done or stopped, how long ago it started and the rewards of its trials. |
| [`HARBOR_NO_JOBS`](../troubleshooting.md#harbor_no_jobs) | You ran `dockingbird harbor jobs` and no Harbor job has run on this Mac yet, or `dockingbird harbor clean` removed them. |
| [`HARBOR_JOB_UNKNOWN`](../troubleshooting.md#harbor_job_unknown) | You ran `dockingbird harbor results` with a name that is no Harbor job on this Mac. |
| [`HARBOR_JOB_RESULTS`](../troubleshooting.md#harbor_job_results) | You ran `dockingbird harbor results` for one job: its state, one row for each trial it ran, and its folder. |
| [`HARBOR_CLEAN_QUESTION`](../troubleshooting.md#harbor_clean_question) | You ran `dockingbird harbor clean` on a terminal, without `--yes`: the job folders it would remove (with `--all`, Harbor itself too), each with its size, and the question whether to remove them. |
| [`HARBOR_CLEAN_ROW`](../troubleshooting.md#harbor_clean_row) | One job folder of the question `dockingbird harbor clean` asks: its name, its size and its state; a job that is still running is named as staying. |
| [`HARBOR_CLEANED`](../troubleshooting.md#harbor_cleaned) | You ran `dockingbird harbor clean` and it removed something: the job folders and the space they freed, what earlier jobs left in Docker (containers, networks, volumes, and what the jobs built), and, with `--all`, Harbor itself. |
| [`HARBOR_SIZES_UNREAD`](../troubleshooting.md#harbor_sizes_unread) | `dockingbird harbor clean` couldn't read the size of some files in a Harbor job's folder or Harbor's install, so the sizes it shows leave them out. |
| [`HARBOR_CLEAN_LEFT`](../troubleshooting.md#harbor_clean_left) | `dockingbird harbor clean` couldn't remove a Harbor job's folder, Harbor itself with `--all`, Harbor's cache, something in Harbor's tmp folder or a job's lock file; it is still where the message says, and you can remove it yourself. |
| [`HARBOR_NOTHING_TO_CLEAN`](../troubleshooting.md#harbor_nothing_to_clean) | You ran `dockingbird harbor clean` and there was no job folder, no leftover and nothing else of Harbor's to remove. |
| [`HARBOR_CLEAN_KEPT`](../troubleshooting.md#harbor_clean_kept) | You ran `dockingbird harbor clean` and some of it was kept. |
