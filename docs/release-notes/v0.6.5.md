# Dockingbird v0.6.5

Release v0.6.5 is the nineteenth tagged version of Dockingbird. It adds `dockingbird fleet hosts set`, `rename` and `forget`. The fleet places a swarm in the pool's host order. The Dockingbird GUI 0.1.11 comes with it.

## Install or update

```bash
UV_INDEX_ZEUSFYI_USERNAME=license UV_INDEX_ZEUSFYI_PASSWORD="$(pbpaste)" uv tool install dockingbird --index zeusfyi=https://license.zeus.fyi/simple/
dockingbird update
```

With a license key, install from Zeusfyi's release index. Copy the key from your purchase email, then run the first line. The operator guide's "Install" section gives the Linux form and `dockingbird license activate`.

An installed Dockingbird takes this release with `dockingbird update` alone. The update installs the Dockingbird GUI 0.1.11 in place of 0.1.10. A GUI that is already open keeps its version until its server stops.

An update made while agents run is staged and taken once the last agent ends. `dockingbird --version` prints `0.6.5`. The Dockingbird GUI is not yet available to customers.

## What v0.6.5 changes

### Adding, renaming and forgetting a host

`dockingbird fleet hosts set NAME --ssh DEST` adds another computer. Use `--gcloud VM --zone ZONE --project PROJECT` for a cloud VM. The command reads the host's Docker and Dockingbird homes. It writes the host into `hosts.toml` only when that worked.

When the command fails, nothing is saved and the message says what to try.

`dockingbird fleet hosts rename OLD NEW` and `dockingbird fleet hosts forget NAME` edit the file too. Your own computer is `local` in every fleet line. `local` cannot be a host's name.

A host has one name across your file, the fleet pool and swarm definitions. A rename of a host the pool holds is refused until it is removed there.

A home that holds only a hand-written `hosts.toml` or `fleet.toml` is now used as Dockingbird's own. Commands no longer refuse it with `HOME_NOT_EMPTY`. A folder with anything else is still refused, and the message lists what it found.

### Placing a swarm

A swarm definition may now leave out its `[placement]`. The swarm then goes to every pool host that takes swarms, in the pool's order.

`--rank N` on `dockingbird fleet hosts add` or `dockingbird fleet hosts policy NAME` sets that order, 1 first. Each swarm gets a home the fleet chooses.

The fleet places a swarm on the first host in that order with room and green lines. It passes over a host whose home has no clone of the swarm's repository. The next host takes the swarm in the same pass. `dockingbird fleet why ID` names the home it passed over.

When a home's `[[home]]` in `hosts.toml` names `clones`, a folder, the worker fetches the swarm's branch into a clone of its own there. It makes the clone from the home's clone of the repository, on any branch. Nobody links a branch into a home by hand.

When the worker cannot fetch, `dockingbird fleet why ID` names the home with no clone to fetch from. For a failed fetch it gives git's own last line. Check that the branch is pushed and that the host's git reaches the remote. Then run `dockingbird fleet release ID`.

### Starting agents with their swarm and role

The fleet now starts each agent of a swarm with its swarm, role and workload (`--swarm`, `--role`, `--engine`). A home still at an earlier release refuses each start with `dockingbird start: '--swarm' is not an option.`

The fleet holds the workload with the reason `UNKNOWN_OPTION`, and `dockingbird fleet why ID` says `ID is held: UNKNOWN_OPTION`. Update that home, then run `dockingbird fleet release ID`.

### Retiring and replacing agents

A role of a swarm definition may now name `min = 0` when it neither reviews nor tests. `dockingbird fleet retire` can then let its last agent go once it is done.

`dockingbird fleet replace` now recovers an agent whose last turn failed or whose process crashed. It does what you would do by hand: stop, then pick up. `fleet retire` of such an agent waits until nothing is open in its inbox.

### Refused starts

Two refusals now name a delete command. One is a start refused because the name belongs to the other tool's kept copy or ended agent. The other is a `--new` refused because the name's copy is kept.

`dockingbird clean NAME --yes` deletes that agent's copy, results and history and frees the name. It appears beside the pick-up. The pick-up stays the one step `dockingbird ui` offers.

### Sampling and inboxes

The fleet worker now samples its host every 30 seconds whatever its homes' inboxes hold. Before, a home with thousands of open rows made every sample late. The host then read `idle_millicores unread` and the fleet admitted nothing to it.

The homes' inbox and checkout reads now run on a thread of their own.

The engine now marks read the open status rows of its own agents once they are gone. That covers agents that retired or died, and agents whose swarm is done or cancelled. It marks up to a hundred rows per home every 30 seconds, so an engine home's inbox no longer grows with every finished swarm.

A question from such an agent stays open. So does any row from an agent the engine did not start.

### Sending and turn reports

A plain `dockingbird send NAME TEXT` now asks the coordinator for NAME's open questions alone. It answers the one question or starts a task however many rows your inbox holds. The refusal that said too many deliveries were pending is gone.

An agent's turn reports no longer pile up in your inbox. Each new `turn N` row from an agent replaces its previous one, and each `turn N failed` row its previous failed one.

Every earlier report stays readable by its id (from `--json inbox` or `wait`) and in its thread.

### The Dockingbird GUI 0.1.11

The GUI adds, renames and forgets a host from its sidebar, with `dockingbird fleet hosts set`, `rename` and `forget`. The GUI is not yet available to customers.

A right click on the DOCKINGBIRD heading opens its menu, "add a host…". Its questions ask over ssh or a gcloud VM, then the ssh destination, or the VM's name, zone and project.

The next question asks for the host's name in the sidebar. A name from the destination is offered when it is free. Over ssh, the form also asks for PATH for docker there and the docker host URL there, each optional.

A right click on a fleet host's heading opens its menu. "rename…" asks for the new name with the old one offered. "forget…" forgets the host once you type `y`. `local`, this computer, has neither.

The Dockingbird layer's `h` asks the same from the keyboard. While a change runs, the command bar's note says so, then gives the command's answer. A tap on a note the bar cuts short opens it whole.

The DOCKINGBIRD heading now shows as soon as `dockingbird fleet hosts` answers, with this computer alone too. A first host can be added on a fresh install.

While any of the GUI's Dockingbird forms is open, a drag over a pane still selects and copies. The copy view still opens, so a destination or a name can be copied from a pane into the question.

Every right-click menu's items now sit one cell in from its border. A popup drawn over bold text no longer paints its border bold, which a terminal without font fallback showed as missing-glyph boxes.
