
A role of a swarm definition may now name `min = 0` when it neither reviews nor tests, so `dockingbird fleet retire` can let its last agent go once it is done, and `fleet replace` now recovers an agent whose last turn failed or whose process crashed, the way you would by hand (stop, then pick up); `fleet retire` of such an agent waits until nothing is open in its inbox.

A start refused because the name belongs to the other tool's kept copy or ended agent, and a `--new` refused because the name's copy is kept, now also give the command that deletes that agent's copy, results and history and frees the name, `dockingbird clean NAME --yes`, beside the pick-up; the pick-up stays the one step `dockingbird ui` offers.

Deploy: the fleet now starts each agent of a swarm with its swarm, role and workload (`--swarm`, `--role`, `--engine`), so install this release on every engine home before its host's worker, in the order `dockingbird update` already uses on each host, and upgrade the fleet database as the operator guide says ([The fleet scheduler](../operator-guide.md#the-fleet-scheduler), the sentence beginning "A fleet database made by an earlier build is upgraded instead") before the workers restart: a worker of this release on a database without migration 0003 fails at its first read of the assignments, on `reviewer_told` and `tester_told`. A home still at an earlier release refuses each start with `dockingbird start: '--swarm' is not an option.`, and the fleet holds the workload with that refusal's id as the reason, `UNKNOWN_OPTION` (`dockingbird fleet why ID` says `ID is held: UNKNOWN_OPTION`): update that home, then `dockingbird fleet release ID`.

Dockingbird now adds another computer for you: `dockingbird fleet hosts set NAME --ssh DEST` (or `--gcloud VM --zone ZONE --project PROJECT`) reaches it, reads its Docker and its Dockingbird homes, and writes it into `hosts.toml` only when that worked; when it didn't, nothing is saved and the message says what to try. `dockingbird fleet hosts rename OLD NEW` and `dockingbird fleet hosts forget NAME` edit the file too, and the GUI's host headings gain the same three. Your own computer is `local` in every fleet line and in the GUI; `local` can't be a host's name. A host has one name across your file, the fleet pool and swarm definitions, so a rename of a host the pool holds is refused until it is removed there. The customer repository `zeus-fyi/dockingbird-sdk` is filled by an export of the product's own documents.
